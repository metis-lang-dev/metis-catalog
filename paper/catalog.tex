\begin{abstract}
A behavior program is useful only when something can load it, run it and
extend it. We describe the \emph{catalog}: one directory per domain, one
manifest, one loader that every consumer shares, and a CI that compiles,
runs and cross-checks every package in two toolchains. We show the
catalog's domains as use cases: story worlds, puzzles, planning, voting,
cellular automata, simulated RDDL worlds, and three device domains with
hosts and intents. For each family we say what it taught the format. We
then describe the \emph{agentic loop}: a model-driven loop that works
through a small set of gated tools over the kernel's REPL. It turns a
program into a package, exercises it against a simulated world, and
proposes extensions; a person approves every write as a diff. We report the
loop porting six story programs for 0.06~USD with the programs byte-equal
to their seeds. We also report it exercising eight RDDL worlds against
pyRDDLGym. The measure is a conditional per-action likelihood, priced on a
declared exact or sampled tier, and it records the programs' disagreements
with the worlds without tuning them. We close with what the loop could not
do, and the rules that forced.
\end{abstract}

\section{Introduction}\label{sec:intro}

A language for behavior programs gives a program a meaning: in metis, a
catalog of typed, weighted linear-logic rules denotes a probability
measure over its own runs \src{S13}. A meaning is not yet a domain someone
can use. Between a program that compiles and a domain a device runs there
are several more needs:
\begin{itemize}[nosep]
\item a place for the program's host, its intents and its extensions;
\item a name the consumers agree on;
\item a start state that both the CI and the live agent read the same way;
\item a record of what the program does on a known case;
\item a path by which the program changes without anyone editing it blind.
\end{itemize}

This paper is about that layer. A metis \emph{package} has two consumers:
a \emph{loop} that develops it and an \emph{agent} that runs it. Both read
it through the same manifest and the same loader (\S\ref{sec:package}).
The catalog's CI is the contract between them: every package is run
against a committed trace and built into a bundle, and both toolchains
must agree on both (\S\ref{sec:ci}). The domains themselves, 29 packages
today, are the use cases. They are what the format had to absorb
(\S\ref{sec:cases}).

The second half is the \emph{agentic loop} (\S\ref{sec:loop}): a language
model working the kernel's REPL and the domain agent through generated
tools. Its one capability that neither interface has is writing into the
catalog, and every such write is a diff a person approves. That gate is
the invariant this paper keeps returning to. Two case studies report what
the loop did with it: porting six story programs (\S\ref{sec:fiction}),
and exercising eight simulated worlds whose measure needed the watch
itself to change (\S\ref{sec:rddl}). Section~\ref{sec:limits} lists what
the loop could not do and the rules that forced.

\paragraph{The stack.} metis has three layers and three papers. The
\emph{language} paper, \emph{Behavior Programs as Measures over Proofs}
(draft 0.3), gives the semantics, the compiler \metisc, the referee
\metispy, and their parity \src{S13}. This paper is the second layer: the
catalog and the loop. The third, \emph{Small Models, Certified Behavior}
(in preparation), is the agent: a small local model made
domain-competent by a certified runtime.

\section{The package}\label{sec:package}

A package is a directory, \texttt{domains/<name>/}, with a manifest,
\texttt{domain.yaml}. The package's name is its directory's. Every
manifest key is optional, and the loader refuses any key it does not know
\src{S1}. The keys:
\begin{itemize}[nosep]
\item \tool{program}: the program file;
\item \tool{extensions} and \tool{serves}: the served program;
\item \tool{host}: a Python factory for the world;
\item \tool{intent}: the spec of the person's verbs;
\item \tool{clock}: env beats per tick, and the watch's settings (\S\ref{sec:rddl});
\item \tool{records}: where surprise records go;
\item \tool{reload}: the agent's reload policy when the package's files change (propose, or auto);
\item \tool{display}, \tool{line}, \tool{voice}: the narrator's name, the console line, the voice;
\item \tool{agent}: a domain-agent module, when the generic one does not fit;
\item \tool{pair}, \tool{partner\_of}: two cooks stepped in one env;
\item \tool{notch}: a fitted overlay of weights.
\end{itemize}
One loader, \texttt{metis\_catalog}, reads every manifest for every
consumer: the domain agent (Python and Go), the loop's SDK, the two
consoles and the CI.

Figure~\ref{fig:dog} shows the dog, the reference device domain. Its
program is 286 lines; its host is a Python file; its \texttt{intent.yaml}
is written by people. Everything under \texttt{intent/} is generated from
it \src{S1}:
\begin{itemize}[nosep]
\item the grammar the intent pass is held to (\texttt{dog.gbnf});
\item the prompt;
\item the spoken examples;
\item the corpus.
\end{itemize}

\paragraph{Extension, pack, bundle.} Three words, kept apart \src{S1}.
\begin{itemize}[nosep]
\item An \emph{extension} is a catalog in the package's
  \texttt{extensions/} that \texttt{extends} the program. The served
  program is the program plus its extensions in name order. The plant's
  \texttt{extensions/visitor.llp} is one: a rule for a visitor who waters
  the plant.
\item In the REPL, a gated candidate is a \emph{pack} (the language's
  word). Once accepted into a package it is written as an extension.
\item A \emph{bundle} is what the emitter forms from a package for the C++
  and Go runtimes: \texttt{ground.wire} and \texttt{sidecar.json}, with
  \texttt{program.ir} and \texttt{tools.json}. The OCaml compiler writes
  \texttt{ground.wire} (\texttt{metisc --wire <program> [--extension
  e.llp]...}). metispy's emitter must produce the same bytes; the catalog's
  CI checks this for every package (\S\ref{sec:ci}).
\end{itemize}

\paragraph{The start is the program's.} A program's \texttt{\#init} lines
are its live start: the domain agent, the consoles and the watch all read
them, and \texttt{\#steps} is the watch's horizon. So a line added for CI
must not change the live behaviour. When a package's own start fires
nothing, its CI case lives outside the package, in
\texttt{goldens/cases/<name>.llp}: the program included unchanged, with a
start that fires (\S\ref{sec:ci}) \src{S2}.

\subsection{Story worlds}
The six story programs are ports of Ceptre examples and their follow-ups:
love\_triangle, tragedy, herstory, talespin, three\_pigs and
three\_pigs\_connectives. The loop brought them into the catalog
(\S\ref{sec:fiction}). They are what the format had to absorb for
programs with no device behind them:
\begin{itemize}[nosep]
\item a domain with no intents must still open (\S\ref{sec:limits});
\item a case with an \texttt{\#interactive} choice must run under CI with
  no terminal, the sampler choosing;
\item a ground can be large: talespin's has 105{,}680 events, and \metisc{}
  grounds it in about 130~s, nearly all of the packages job's time

\end{itemize}

\subsection{Puzzles and planning}
wgc (wolf, goat, cabbage) is the one puzzle with a host. Its domain agent
searches the program's moves with a host-side greedy solver, and the
domain agent's step cap exists because of it: a program that never settles
cannot hold the clock (\S\ref{sec:loop}). bridge and bridge\_decl are two
formalizations of one statement, bridge and torch:
\begin{itemize}[nosep]
\item bridge is imperative;
\item bridge\_decl holds minute-marks and pace as data.
\end{itemize}
They are two packages, not a program and its extension: bridge\_decl
does not \texttt{extends} bridge, and a package serves one program
\src{S2}. blocks\_world and tower\_of\_hanoi are Ceptre examples.
tower\_of\_hanoi coexists with the RDDL \texttt{hanoi}, and both READMEs
say which is which.

\subsection{Small formal worlds}
primes is a sieve: every number annihilates its multiples. ll is a toy
linear-logic prover. gossip spreads posts in a small network. fptp counts
ballots. cellular\_automata is an honest skeleton: the original has no
rules, so its committed trace is empty \src{S2}. These are linear logic as
computation. They taught the format that a package need not be a
``domain'' in any device sense: a program with a case is enough.

\subsection{Device domains}
dog, plant and kitchen are the domains the agent speaks for. Each has a
host (the world), and dog and plant have intents. kitchen has a
domain-agent module of its own, and its pair, kitchen\_shared, is stepped
in one env with it. plant carries the catalog's one extension,
\texttt{extensions/visitor.llp}: a visitor waters the plant, which the
program alone has no rule for. These three fixed the manifest's shape
\src{S1}. Their own starts fire nothing (no command is held), so their CI
cases are in \texttt{goldens/cases/} (\S\ref{sec:ci}) \src{S2}.

\subsection{Simulated worlds}
Eight packages are worlds from the IPPC/RDDL benchmarks, run against
pyRDDLGym. In each, the gym is the world and the program is the
formalization:
\begin{itemize}[nosep]
\item nav, hanoi, gol, sysadmin, xtraffic and elevators come from
  metispy's models or the RDDL headers;
\item wildfire and tamarisk were formalized from gym episodes in an
  earlier metis loop, and keep the notch fitted then.
\end{itemize}
Each package's host is a thin configuration over one class,
\texttt{tools/rddl\_host.py}, which owns:
\begin{itemize}[nosep]
\item the gym child process;
\item the fluent-to-atom mapping (\tool{elevator-at-floor\_\_\_e0\_\_f2}
  is the atom \tool{elevator\_at\_floor(e0,f2)}, unless the world maps
  its own);
\item the mapping from fired rules to gym actions;
\item the snapshot and restore the REPL's forks need \src{S7}.
\end{itemize}
There are two kinds of world:
\begin{itemize}[nosep]
\item in an \emph{acting} world (nav, hanoi, xtraffic, elevators) the
  program's rules choose the moves and the gym answers;
\item in an \emph{observing} world (wildfire, tamarisk, and since
  rddl-watch gol and sysadmin) the host acts, either a seeded random
  agent or a no-op, and hands the step to the program, whose pipeline
  computes the next state \src{S7,S8}.
\end{itemize}
Section~\ref{sec:rddl} is about measuring them.

\subsection{What stays outside packages}
Some programs are not packages:
\begin{itemize}[nosep]
\item the RDDL experiments' records (\texttt{domains/rddl/}: born,
  candidate and iteration worlds);
\item the port-plugin conformance fixtures;
\item the C++ runtime's acceptance demo;
\item the CI cases.
\end{itemize}
They keep their roundtrip and diagnose gates. The road catalog
(chariot's production road-behavior catalog, its scenes and its packs) was
outside until road-collapse made it one parked package. Its program is
the production catalog included unchanged on one scene, one tick, so that
it runs and builds nominally. Its real port, with SUMO as the runtime, is
the next release's subject \src{S16}.

\section{CI as the catalog's contract}\label{sec:ci}

The catalog's CI has two jobs (Table~\ref{tab:ci}).
\begin{itemize}[nosep]
\item \texttt{catalogs} compiles every \texttt{.llp} file, packages or
  not:
  \begin{itemize}[nosep]
  \item a roundtrip;
  \item \metisc's diagnostics, with each exemption listed with its reason;
  \item the canonical-key gate: scene instances ground to committed keys;
  \item a crosscheck that metispy compiles every file \metisc{} does.
  \end{itemize}
\item \texttt{packages} gives each package three gates \src{S2}:
  \begin{itemize}[nosep]
  \item \emph{run}: \texttt{metisc --run} of the program's
    \texttt{\#}~case, stdin closed, equals the committed
    \texttt{goldens/traces/<name>.txt} byte for byte;
  \item \emph{twin}: metispy's replay of the same case gives the same
    start, fired and final lines;
  \item \emph{wire}: \texttt{metisc --wire} of the served program equals
    metispy's bundle \texttt{ground.wire} byte for byte.
  \end{itemize}
  The cases in \texttt{goldens/cases/} get the run and twin gates.
  Every tracked package needs a trace, and every trace a package or a
  case.
\end{itemize}

Before the CI pinned anything, both toolchains had to be shown
deterministic. \metisc's \texttt{--run} seeds the reference sampler with
the seed index; run twice, it was byte-equal on all 28 packages, and
metispy's replay gave the same start, fired and final lines \src{S2}. The
query lines are hit counts over the seeds, and metispy annotates them
with exact probabilities that \metisc{} does not print. So the twin
compares the other lines only, and nothing pins noise.

\paragraph{Live-neutral lines, and cases.} A program's \texttt{\#init} is
its live start (\S\ref{sec:package}). So only lines that leave the live
behaviour alone may be added for CI: \texttt{\#steps 6} (the watch's
default horizon) and \texttt{\#seeds}. \texttt{\#query} is not
live-neutral: the console's mirror projects every query on each call
\src{S2}. Where a package's own start fires nothing (dog, plant, kitchen,
sysadmin), its CI case is a separate file. That file includes the program
unchanged, gives a start that fires, and has a trace of its own. The cost
is honest and stated: dog's case repeats its program's 32
\texttt{\#init} lines, because directives are read from the file that is
run, not from its includes \src{S2}.

\paragraph{A bug the CI script had.} The first \texttt{packages.py} ran
its gates in threads, and read \metisc's output through a pipe. While a
thread computed talespin's Python twin, it held the interpreter lock and
starved the pipe's reader. \texttt{metisc --wire}, 56~MB of output,
stalled for over 13 minutes, against 119~s alone. Each gate now runs in
its own process, writing to a temporary file \src{S2}.

\section{The agentic loop}\label{sec:loop}

The agentic loop is a language model, hosted in pi, working two processes
through generated tools \src{S9}:
\begin{itemize}[nosep]
\item the kernel's REPL (metispy, over its JSON-lines wire);
\item the domain agent (metis-agent's lower half, which runs a package
  with its host and intents).
\end{itemize}
The loop's tools are generated from those two interfaces' own
declarations. Nothing is written for pi that the interfaces do not
declare, and nothing they declare is left out. pi's built-in tools,
context files, skills, prompt templates and MCP are all off.

\begin{table}[t]
\small

  program, checked whole & \tool{repl\_text}, \tool{repl\_formalize},
  \tool{repl\_revise} \\

  validated write, gated & \tool{catalog\_apply} program \\

  atoms, gated & \tool{catalog\_apply} intents \\

  \tool{domain\_open}, \tool{domain\_clock}, \tool{intent\_<verb>} \\

  and seeded episodes; recorded, not fixed & \tool{domain\_ports},
  \tool{domain\_episodes} \\

  enters the loop & (a signal) \\

  \tool{repl\_mine}, \tool{repl\_gate} \\

  formalize & \tool{catalog\_edit} \\

  a commit & \tool{catalog\_take} \\
\bottomrule
\end{tabularx}

\label{tab:loop}
\end{table}

Table~\ref{tab:loop} is the loop as a state machine. Three kinds of tool
matter:
\begin{itemize}[nosep]
\item \textbf{the REPL's verbs} (\tool{repl\_state}, \tool{repl\_show},
  \tool{repl\_text}, \tool{repl\_formalize}, \tool{repl\_revise},
  \tool{repl\_gate}, \ldots), one per verb the wire lists;
\item \textbf{the domain agent's faces} (\tool{domain\_open},
  \tool{domain\_clock}, \tool{domain\_state}, \tool{domain\_events},
  \tool{domain\_ports}, \tool{domain\_world}, \tool{domain\_episodes}),
  and one \tool{intent\_<verb>} per verb of the domain's
  \texttt{intent.yaml};
\item \textbf{the three writes} into the catalog, which neither interface
  has:
  \begin{itemize}[nosep]
  \item \tool{catalog\_apply} writes a program, an extension, a served
    seed, a README or the intents;
  \item \tool{catalog\_edit} makes one exact edit of a file, old text to
    new;
  \item \tool{catalog\_take} brings a finished domain into the person's
    catalog.
  \end{itemize}
  All three go through metis-loop's SDK, which has one Python face and one
  TypeScript face at one tag.
\end{itemize}

\paragraph{The gate.} Every write waits at pi's \texttt{tool\_call} gate.
The gate shows the SDK's dry-run diff, and the person answers yes, or no
with a steer. Two details make the gate readable rather than decorative
\src{S9,S10}:
\begin{itemize}[nosep]
\item a file the person refused shows, at its next proposal, the diff
  from the refused text first, then the diff against the disk;
\item a README the person refused is never written: it comes back through
  the same gate.
\end{itemize}
The extensions' code decides nothing about the domain. It spawns the
processes, generates the tools, passes calls through, turns unasked lines
(events, quiescence, surprises) into messages, and refuses an apply whose
candidate has not passed its gate. The model decides the order of calls
and what a surprise means. The person decides every write, and steers and
stops.

plant's visitor extension, applied to a copy of the plant without it.

\paragraph{The seed task.} A seeded run makes an existing program a
package. The seed task has six steps \src{S9}:
\begin{enumerate}[nosep]
\item read the program;
\item apply it as served;
\item the intents, or none;
\item exercise it;
\item a README;
\item a take, when the person asks.
\end{enumerate}
It states the rules that the case studies below forced:
\begin{itemize}[nosep]
\item no formalize or revise of a seed, ever: they reprint the program and
  drop its comments;
\item a change the person asks for is a \tool{catalog\_edit} with the
  exact old and new text;
\item every claim in a README needs a source the model can name;
\item one run is one sample, never ``always'' or ``only'';
\item a world without intents is measured with the person's $n$, set
  before the task begins, and recorded, never fixed.
\end{itemize}

  Because the README was never applied, the gate showed it as new each
  time, and the person caught the damage only by diffing against the
  refused version. The fix was the gate's diff from the refused proposal
  \src{S10}.
\item \textbf{Invented facts in READMEs.} Four of six READMEs needed a
  refusal despite the instruction ``copy those, invent none''. One
  misquoted the author. One claimed ``only the brick house survives'',
  which is false when the wolf reaches the brick house first, and
  generalizes from one sampled run. One misquoted the program's own
  catalog name. The fixes: the SDK writes a README's mechanical parts from
  the files (origin, header, how to run, intents), and the model writes one
  paragraph in which every claim needs a source \src{S9,S10}.
\item \textbf{Gaps in the seed task}, which cost every run extra reads.
\end{enumerate}
The plain summary is the report's own: the gate held every time, and a
README a model writes must be read like code \src{S4}.

\section{Case study B: exercising simulated worlds}\label{sec:rddl}

A world without intents is exercised through its world. Its ports name
the gym, the instance, the observed atoms and the actions.
\tool{domain\_episodes} runs $n$ seeded episodes. Each is a reset with its
seed, on both the program's sampler and the gym, with every beat scored to
the episode's end \src{S9}.

\paragraph{The measure.} Score a beat by the program's probability of
the world's reading, and it prices the program's own choice of action. A
wrong rate can then look better. On nav, seeds 1--20, the per-beat
likelihood ranked a die rate five times the instance's best (Table~\ref{tab:nav})
\src{S5}. The measure the loop uses is conditional instead: per action
the program sent, $P(\text{the world's answer} \mid \text{that action})$.
That is the weight of the same-action alternatives in the drawn tier
whose effect is the world's reading, over the weight of them all. It is
RDDL's own transition model, scored only when the program's state agreed
with the world's before the action. It ranks the true rate best. Each
variant is still scored on its own trajectories, so the scored-action
count is reported beside every mean.

\paragraph{A planted wrong rule is caught.} The surprise test is the
kernel's, unchanged: a reading the served program gives zero probability
opens a record. With nav's die rules deleted, 18 of 20 episodes surprise:
the robot vanishes and the program cannot say so \src{S5}. On gol, with
the rule for a dead cell coming alive deleted, the test requires surprises
in at least 3 of 5 episodes, each naming a birth \src{S14}.

\paragraph{The lockstep problem.} The first pass over the seven new
worlds (rddl-worlds step~3) measured nav and hanoi fully, but none of the
other six \src{S7}. Six of the seven compute one gym step as a cycle of
many rows, and the watch read the world after every row. That went wrong
in four ways:
\begin{itemize}[nosep]
\item \textbf{a mid-cycle read surprised.} gol's mark pass consumes a cell
  the gym still shows; xtraffic's gym answers a move with the obstacles
  already shifted, which the program reaches 13 rows later.
\item \textbf{a pipeline was not restarted at a tick.} wildfire and
  tamarisk stalled at their second step.
\item \textbf{exact pricing of a 78-row cycle was too slow.}
\item \textbf{after a mismatch the program could still explain, the watch
  never re-checkpointed.} elevators went from 0.1~s to 22~s a row by
  step 12.
\end{itemize}
Two worlds also never really started. sysadmin had no start token, and
elevators' \texttt{\#init} was not the gym's reset state. And one
engineering failure belongs in the record. A host snapshot that grew with
every fired event, stored once per row, took a diagnostic to 23.7~GB in two
minutes. The snapshot now holds the episode only, bounded by the horizon
\src{S7}.

\paragraph{The fix, behind the manifest's clock (rddl-watch).} Every
change is a setting a package declares. Without it the watch is unchanged,
and the Python and Go agents stay byte-equal on their recorded days
\src{S8}.
\begin{itemize}[nosep]
\item \texttt{clock: \{lockstep: true\}} (gol, xtraffic, sysadmin,
  wildfire, tamarisk) reads the world once per pass of the stage
  pipeline. The pass is done when it wraps (a link back into the first
  stage) or when nothing is left to fire; both are read off the program's
  own stages, with no per-world constant. A wrapped pass waits for the
  beat, and the beat's input restarts a quiet pipeline at its first
  stage. Every beat is the window's boundary.
\item \texttt{clock: \{follow: true\}} (elevators, a one-stage program
  that never rests) adopts a reading the program explains as one exo row,
  and moves the checkpoint there. With its host reading only after a row
  that stepped the gym, a window runs from one gym step to the next.
\item sysadmin's host hands its start token when the program lacks it,
  and every RDDL world now starts at the gym's reset state, through the
  same exo row the world lines use.
\item The Go agent refuses both settings by name.
\end{itemize}

\paragraph{The tier.} The exact filter is the default. A window whose
exact filter outgrows 10{,}000 cumulative retained states goes to a
sampled tier: 500 reference-sampler runs, seeded from the episode's seed
and the session's position, with a 95\% Wilson half-width \src{S8}.
Every record and score declares its tier, and the sampled tier's runs are
the reference sampler's own draws, indexed once per window. gol's pass
needs 6{,}665 states and stays exact. wildfire's and tamarisk's need more
than 300{,}000, so they are sampled. A sampled zero is no proof: it means
no run of 500 reached the reading, below the tier's resolution ($p <
0.0076$ at 95\%). So it is kind \emph{rare}, never a surprise, and the
loop counts it apart \src{S8,S9}. Tamarisk shows why: four of its zeros
at $n=500$, re-drawn at $n=20{,}000$, were $p \approx 0.0065$, $0.0015$,
$0.0001$ and below $10^{-4}$ \src{S8}.

Table~\ref{tab:rddl} is the result. The surprises the watch itself
produced are gone. What remains is the programs' honest disagreement,
recorded for a tuning subject and not fixed \src{S8}. Elevators surprises
in every episode, at gym steps 1--33, in two ways:
\begin{itemize}[nosep]
\item in 18 episodes, an arrival falls in a gym step whose window held only
  the action row: the program draws arrivals as rows of their own between
  actions, while the gym draws them inside its step;
\item in 2 episodes, the gym boards a passenger at \texttt{close}, where
  the program boards only while the door is open.
\end{itemize}
The most mismatched atoms are expected sampling elsewhere, except
xtraffic's obstacle arrivals at the road's edge.

\paragraph{Through the loop, and the cost.} A real loop run read the
same measure: one pi run on gol through \tool{domain\_open},
\tool{domain\_ports} and \tool{domain\_episodes}. Its 20 episodes gave the
domain agent's numbers (820 beats scored, mean log $-0.974$, no surprise),
both gates were byte-equal, and the take was identical \src{S8}.
\begin{itemize}[nosep]
\item That run cost 0.017~USD by pi's count, 0.051 by the key's usage over
  its window \src{S8}.
\item nav's loop run (rddl-worlds step~2: the package taken byte-equal,
  its measure the domain agent's) cost about 0.006~USD by the key \src{S6}.
\item The nine loop runs of rddl-worlds step~3 came to 0.221~USD by pi's
  count and 0.125 to 0.154 by the key \src{S7}.
\end{itemize}
No run tuned anything: no weight, no notch, no extension.

\section{What the loop could not do, and the rules it forced}\label{sec:limits}

Each finding below changed a component, and each is a commit.
\begin{itemize}[nosep]
\item \textbf{A program-only domain must open.} The story worlds have no
  intents and no host. The domain agent now builds them as bare domains
  (an empty card, no plugin) in Python and Go. Every intent then gets the
  same refusal in both, ``this domain takes no intents''. A new recorded
  day holds them at parity: 27 output lines equal \src{S11}.
\item \textbf{\texttt{metisc --run} on an \texttt{\#interactive} case with
  stdin that is not a terminal} spun at full CPU and printed nothing.
  After end of input, every later choice is now the sampler's, and the
  case header is flushed before the ground \src{S4,S11}.
\item \textbf{A take must be byte-preserving.} Elevators' header, kept
  verbatim from the RDDL file, came back with LF line ends instead of CRLF.
  Take, plan, apply and edit now keep a file's bytes \src{S12}.
\item \textbf{A notch is carried, never edited.} Take did not carry a
  manifest's notch, so wildfire and tamarisk could be neither served nor
  taken. It does now, and an edit of a notch is refused: no loop tool
  writes weights \src{S12}. Porting and exercising have one budget;
  tuning has another, and a separate subject.
\item \textbf{The model ran $n=20$ before the person's cap arrived}, twice:
  in rddl-worlds step~3 and again in the gol run. The person's $n$ is now
  set before the task begins (\texttt{loop.sh --episodes}), and the seed
  task carries it \src{S9}.
\item \textbf{The SDK serves a program only as \texttt{<name>.llp},} and
  the model misread the refusal for a whole settle. The refusal now says
  what to do \src{S7}.
\end{itemize}
And the person's own rule, which no component enforces: approve only the
diffs you have read. Twice, the person's check (a byte comparison, or a
diff against the refused version) found what the model's account of its
change did not say \src{S4}.

\section{Related work}\label{sec:related}

The story worlds are ports of Ceptre, Martens' linear-logic language for
interactive narrative, and its examples. metis keeps Ceptre's
multiset-rewriting reading and adds a measure \src{S13}. The simulated
worlds are IPPC benchmarks, written in RDDL and run in pyRDDLGym; here the
gym is the world a formalization is measured against, not a planner's
environment. The agentic loop sits among coding agents that edit code with
tool calls under human approval, and among program synthesis with
execution feedback. What it adds is narrower: every write goes through one
validated SDK and a person's diff; the loop's tools are generated from the
interfaces it drives; and it measures a program against a world rather
than against tests. We make no comparative claim. This paper reports one
system's runs, each one sample.

\section{Conclusion and next}\label{sec:conclusion}

A program becomes useful as a package: one manifest, one loader, a
committed case and trace, a bundle both toolchains agree on, and a CI that
says so for every package on every push. The agentic loop grows packages
under a gate a person reads. In the two case studies it ported six
programs byte for byte for 0.06~USD, and it exercised eight worlds to a
measure that records disagreement instead of hiding it.

Three subjects come next.
\begin{itemize}[nosep]
\item \textbf{Tuning.} A tuning subject, budgeted apart, starts from
  Table~\ref{tab:rddl}. The open question is scoring models on one fixed
  set of recorded transitions, rather than on each model's own
  trajectories \src{S5}.
\item \textbf{SUMO for road.} The road domain gets SUMO as its runtime,
  and a real port \src{S16}.
\item \textbf{Intents for worlds.} Worlds that take commands get intents.
\end{itemize}
